# Role-Based Access Control (Step 5)

All access rules live in [`app/rbac.py`](../app/rbac.py) and are enforced on the server. Hiding a menu item is only a convenience: a user who types `/api/page/<id>` directly gets **403**.

| Capability | Meaning | Admin | Franchise Owner | Store Manager | Staff | Auditor |
|---|---|---|---|---|---|---|
| `copilot` | Use the AI Copilot and its saved chats | ✓ | ✓ | ✓ | ✓ | ✓ |
| `view` | Read the agent pages, open the outlet detail drawer | ✓ | ✓ | ✓ | | ✓ |
| `run` | Run the agents (`/api/run_cycle`, `/api/run_agent`) | ✓ | ✓ | | | |
| `resolve` | Log an inspection (Audit page) | ✓ | ✓ | ✓ (own outlet) | | |

The Auditor is strictly read-only. Admin also holds the Freight-edition capabilities (`quote`, `approve`, `admin`) so no legacy route breaks.

## Outlet scope

Store Manager and Staff are limited to **one outlet** (`user["outlet"]`); the other roles see every outlet.

- `ctx(user)["scope"]` is the outlet id (or `None` for all). A scoped account with **no outlet assigned gets 403 everywhere**, and an **unknown role gets 403 everywhere**.
- Pages, KPIs, tickets, the live pulse and the detail drawer are filtered by the scope. A request that names another outlet (page parameter, tab, detail id, Copilot question) is refused with 403 (for the Copilot, with a polite refusal).
- Chain-wide extras are hidden from scoped roles: agent summaries and scores, sentiment issue categories, stock-transfer suggestions (they list other outlets).
- Writes (reviews, inspections) by a scoped role must target their own outlet.
- The Copilot gets `scope` and a PII `mask` (Staff and Auditor never see salary or personal data). A safety net refuses any answer that would mention another outlet, even for intents added later.

## What the other members need

| Member | Contract |
|---|---|
| Auth (1) | `user_of(request)` in `server.py` must return a dict with `email`, `username`, `role` (one of `rbac.ROLES`) and `outlet` (needed for Store Manager and Staff). Raise 401 for a missing, invalid or locked user. Store the role and outlet in the `users` table. |
| Admin dashboard (3) | Protect every route with `need(ctx(u), "users")`. Register the `admin` and `profile` pages in `V.PAGES`; they then appear in the menu automatically for the roles that may open them. Role names for promote/demote: `rbac.ROLES`. Render `rbac.permission_table()`. Keep at least one Admin (that rule is yours). |
| Copilot (4) | Pass `scope` (and `mask`) to everything you add in `analyst.py` / `qa.py`; filter by `outlet_id = scope` when it is set. The server already blocks other outlets' ids in questions and answers, but do not rely on that alone. |
| UI (5) | `/api/me` returns `menu` (already filtered), `caps` and `scope`. Use `caps` to hide buttons; the server is the real guard. Show the `msg`/`detail` of a 403 clearly. |

## Decisions the team can change in `rbac.py`

- Franchise Owner sees **all** outlets (the matrix says "all agent pages").
- Store Manager may log inspections and reviews for their **own** outlet (the PDF only says "cannot run agents").
- Salary and personal data are hidden from **Staff and Auditor** in the Copilot.
